# Admin Template

基于 React、Vite 和 Ant Design 的管理端消费者模板，包含用户、角色、权限、配置、积分及日志等现有页面。它通过公开的 `@zucker-framework/*` 入口接入后台，不需要相邻 Framework 源码。

## 独立项目使用

使用已核验版本的 Zucker CLI 初始化 Admin 项目。CLI 负责把模板开发用的 `workspace:*` 换成固定制品版本；不要直接复制未转换的 manifest 并当作独立项目安装。

1. 在生成项目目录执行 `pnpm install`，保存本项目 lockfile。
2. 将 `.env.example` 复制为 `.env.local`；默认 `API_PROXY_TARGET=http://localhost:4200`，应填写后端 origin，不带 `/api`。
3. 启动本项目对应的 Server，再执行 `pnpm dev`。Admin 默认端口 `4201`，浏览器仍请求同源 `/api/*`，开发代理保留该路径前缀。
4. 执行 `pnpm lint`。应用源码类型可用 `pnpm exec tsc --noEmit -p tsconfig.json` 检查。

配置仅保留项目内 `@/* → src/*` 别名；`fe-form` 等依赖从已安装的公开包解析。类型与 ESLint 配置均在项目内，不继承 Framework 根配置。

静态托管时需由部署入口转发 `/api/*` 并提供 SPA 路由回退；Vite 开发代理不是生产反向代理。登录与管理数据依赖已配置的 Server、持久化和权限，页面存在不代表已完成这些服务接入。模板没有默认管理员密码。

配置回归使用 Node.js 22.22 或更高版本执行 `node --test config.test.mjs`，只核对本地配置，不启动应用或调用真实服务。

## 管理端语言

默认语言为中文，登录页和管理页顶栏可以切换 English / 中文。选择仅以
`zucker-admin-locale` 保存到本机浏览器；浏览器禁止存储时仍可在当前页面切换。
语言变化更新 Ant Design / ProComponents 的通用表格、分页、表单文案及页面内容，
不重新挂载路由，不重置正在编辑的草稿；页面地址、资源编号和服务端权限不随语言变化。

`src/i18n` 复用现有 Zustand 状态和 Ant Design locale，提供
`useAdminI18n()`、`t(中文, English?, 参数?)` 和 `localeTag`。通用短词与页面词典分别维护，
消费者可为自己的页面加入明确双语文案；金额、日期使用当前 locale 格式。
这与服务端动态翻译字典管理是不同能力，未接持久化的旧 i18n 管理页仍保持未启用。

默认 starter 菜单只有 ID、原始名称和路径均匹配时才本地化。自定义菜单、改名的默认菜单、
用户名称、角色名称、内容正文、文件名及其他业务记录保留原值，不作为词典键批量替换。

## 用户、角色与基础编辑

新建用户沿本模板注册政策显式使用 `member` 类型，编辑已有用户保留其分类。
用户列表的角色分配使用既有 `/users/:id/roles`，需要 `users:authorize` 与角色目录读取权限；
角色目录分页，已选角色跨页保留。每个用户独立加载与维护草稿，读取失败时禁止保存，写入失败
保留选择并允许重试；服务端以事务串行替换完整角色集合。

角色普通资料编辑保留原权限，只有具备授权权限并明确编辑授权时才提交权限列表。
权限定义编辑保持编号不变，只写定义元数据；用户和角色的授权通过各自的授权接口完成。
字典和动态表单使用真实字段与保存接口，失败保留输入，重新读取确认持久结果。
动态表单预览将当前语言的界面提示传给 `DynamicForm.messages`，业务字段名及自定义校验文案保留原值。

## 通用管理入口与真实来源

默认菜单按概览、用户与权限、内容与站点、交易与额度、运行与审计、系统设置分组。显式 `account:admin` 初始化创建缺少的 starter 菜单；不会在启动时重写数据库，也不会覆盖既有自定义菜单。Admin 使用 ProLayout/ProTable 和现有公开前端包，没有新增布局或表格框架。

- 内容管理与博客分类直接调用 `/content/manage`，需要 `content:manage`；保存草稿和发布是分开的操作。
- 站点配置只编辑已经生效的品牌、双语链接与外观；账户/邮件/支付设置不会出现无实际作用的输入框。
- 连接配置需要 `config:query`，状态取自实际 SDK 使用的 Server 启动快照；同时显示已应用/已保存版本和待重启状态。`config:update` 可编辑 API descriptor 提供的支付、登录、邮件、存储、网站分析/广告/客服及六组可选原生AI设置，共16组profile，使用独立加密密钥持久保存，重启 Server 生效。字段默认保持原值与来源，密钥不会回显；替换/清除须明确选择，清除屏蔽环境回退。页面不验证外部服务连通，也不提供生成业务入口。
- 管理订单/订阅、任务、通知投递、文件和日志通过 `/management/*` 的有限字段投影读取。私人支付策略、任务正文、文件存储键和邮件收件人不回显。API 密钥只读列表另需 `api-keys:query`，只显示前缀和元数据。
- 积分查询需 `credit:query`，正向人工发放另需 `credit:grant`；同一事务写入批次、余额、流水与操作审计。结果未知时保持同一申请重试，刷新后重填相同内容也复用请求键。余额和批次独立展示退款待处理额度，该项已从可用额度排除且不与真实保留额度重复计算；账面余额不当作可消费额度。当前没有负调整或新增冻结按钮。
- 退款管理需 `billing:refund`，从已付款的一次性订单或本地订阅付款周期进入。现金退款、额度回收与自动核对分别显示；核对不会重发退款。未知结果复用操作者绑定的申请键读取恢复，仅已准备而未提交的申请允许明确确认后继续首次提交。
- tenant/i18n/旧内存通知模板页面明确未启用，直达也不会发起业务请求。持久投递历史不依赖旧内存通知历史。

真实 API/权限/数据库与浏览器证据见 Server 的 `management.persistent.e2e-spec.ts`、`management.browser.e2e-spec.ts`，连接本地检查见 `connections.metadata.e2e-spec.ts`。浏览器套件显式 `RUN_MANAGEMENT_BROWSER=1`，使用 localhost:4320、本机 Chrome 和随机数据库 schema，不发送真实邮件、不调用付费 AI 或真实支付。

可保存连接设置的 `connections.browser.e2e-spec.ts` 原有7类真实Admin/API/PG证据覆盖基础10组descriptor、密钥保持/替换/清除且不回显或落浏览器存储、CAS冲突保留非密钥草稿、实际重启应用配置、只读权限、390px和缺少加密密钥。新增1项Admin浏览器验证六组原生AI字段和实际加密保存；对应8项SDK/PG/Nest验证通过，没有真实模型调用。显式 `RUN_CONNECTIONS_BROWSER=1`，独占 localhost:4323，结束后清理进程和随机schema。

当前源码检查点的退款P1已修复并完成本地验证：现金成功后来源hold创建/确认失败时，已退来源保持不可消费；余额与批次将退款待处理额度独立列示。现金证明已记录但金额尚未合入时，退款目标显示待核对及“上次已核对”金额，并禁止新申请；明确核对后按服务端结果恢复操作。新增Web额度中英/390px、Admin余额/批次和退款目标各1项实际页面定点通过。I6固定制品消费仍待冻结后执行，本地验证不代表发布。
